# 项目文档索引

项目文档按“**需求编号 → 生命周期分类 → 具体文件**”组织。查阅某项功能时，请优先进入对应的正式需求目录；开发与调研过程记录统一收口在 [90-工作区/README.md](90-工作区/README.md)，不再平铺堆砌在本索引页中。

## 目录约定

| 目录 | 用途 |
| --- | --- |
| `00-公共资料` | 跨需求且长期有效的架构、运维、规范与模板。 |
| `01-*` 至 `89-*` | 一个业务需求或产品能力一个目录；编号固定，不复用。禁止在 `docs/` 顶层新增无编号目录。 |
| `90-工作区` | VibeCoding 工具的计划、调研和过程记录；确认后的结论应转写到正式文档，历史月份按月归档至 `90-工作区/archive/YYYY-MM/`，索引统一维护在 `90-工作区/README.md`。 |

每个需求目录按以下生命周期按需创建子目录（未产生内容无需预建）：

```text
01-需求/      # 业务目标、范围、角色、验收标准（不写具体类名和实现细节）
02-设计/      # 架构、接口、数据、页面和技术约束
03-实施/      # 分阶段计划、迁移步骤、风险与回滚方案
04-验收/      # 测试结果、发布记录、遗留问题与验收结论
99-归档/      # 已被替代的历史文档（替代文档需注明来源）
```
