# 组织架构与数据权限设计方案

> 本文档为“组织架构与数据权限”升级的唯一生效设计基线，所有后端与前端模块均须严格遵循本文档定义的数据模型、权限码体系、数据权限引擎规则与前后端 API 契约。

---

## 1. 升级目标与架构模型

### 1.1 业务目标

1. **菜单升级**：将原一级菜单“用户管理”升级为“**组织架构**”，下设四个二级菜单：**部门管理**、**岗位管理**、**用户管理**、**角色管理**。
2. **用户与管理员统一**：取消将管理员与普通用户割裂维护的模式，统一在“用户管理”中维护。区分内置超级管理员（`account.super_admin = 1`，不可删除、不可禁用、不可通过界面随意授予或撤销）与普通业务管理员（通过角色赋权）；`account` 表改为软删除（`deleted`）。
3. **组织架构解耦模型**：
   - 部门（树形，含物化路径 `ancestors`） ↔ 员工（通过 `account_dept_link` 关联，含 `primary_flag`、`leader_flag` 兼容多部门；初期前端按单主部门交互，`account.primary_dept_code` 冗余主部门编码便于列表展示与数据权限过滤）。
   - 岗位 ↔ 员工（多对多，通过 `account_position_link` 关联）。
   - 角色 ↔ 员工（多对多，复用 `account_role_link`）。
4. **接口路径统一迁移**：用户与角色接口统一迁移至 `/bac/org/*` 前缀下，与部门、岗位形成统一的组织架构接口体系。
5. **角色数据权限体系**：数据范围挂在角色（`role.data_scope`）上，支持 5 种数据范围；多角色取**并集（最大权限优先）**；内置超级管理员默认拥有全部数据权限。首批落地模块：**用户管理**、**登录日志**、**操作日志**。

## 4. 数据权限核心引擎设计（`com.wety.demo.core.datascope`）

### 4.1 数据范围枚举（`DataScopeEnum`）

| 枚举值 | code | 说明 | 解析规则 |
| --- | --- | --- | --- |
| `ALL` | `1` | 全部数据权限 | 直接放行，不追加过滤条件 |
| `CUSTOM` | `2` | 自定义部门数据权限 | 读取 `role_dept_link` 中该角色配置的 `dept_code` 集合 |
| `DEPT` | `3` | 本部门数据权限 | 读取当前账号在 `account_dept_link` 中的部门集合（无记录时回退 `account.primary_dept_code`） |
| `DEPT_AND_CHILD` | `4` | 本部门及以下数据权限 | 本部门集合 + `dept.ancestors` 包含 `",{deptCode},"` 的所有未删除子孙部门 |
| `SELF` | `5` | 仅本人数据权限 | 标记 `includeSelf = true`，仅匹配 `userField = currentUserCode` |

### 4.2 聚合与执行机制

1. **解析规则（`DataScopeResolver`）**：
   - 内置超管（`account.superAdmin == 1` 或兼容存量 `type == "admin"`）直接返回 `all = true`。
   - 多角色按**并集**聚合：任一有效角色为 `ALL` 则 `all = true`；否则合并全部有效角色的可见部门集合与 `includeSelf` 标记；若用户未绑定任何有效角色，默认退化为 `SELF`。
2. **切面拦截（`DataScopeAspect` + `@DataScope`）**：
   - 在需要数据权限过滤的 Service 方法上标注 `@DataScope(deptField = "...", userField = "...")`。
   - 切面支持嵌套调用时的上下文保存与恢复，并在 `finally` 中安全清理 `AppThreadLocal`。
3. **动态查询自动注入（`BaseRepositoryImpl`）**：
   - `BaseRepositoryImpl.generatePredicate` 检测当前线程存在激活且非 `all` 的 `DataScopeContext` 时，先检查当前查询实体的 JPA Metamodel 是否包含 `deptField` 或 `userField`。
   - 若实体两者皆不含（如辅助表查询），跳过注入；若至少含其一，则自动拼装 `deptField IN (...) OR userField = currentUserCode`；若均无有效条件，则注入 `cb.disjunction()`（恒假），杜绝越权。
4. **单条操作防水平越权（`DataScopeChecker`）**：
   - 提供 `isAccessible(String targetDeptCode, String targetOwnerUserCode)` 和 `assertAccessible(String targetDeptCode, String targetOwnerUserCode)`。
   - 在详情查询、修改、删除、启停、重置密码等单条写/读接口中调用 `assertAccessible`，越权时返回错误码 `402`。

### 4.3 首批业务落点配置

| 业务模块 | 目标实体 | `@DataScope` 注解参数 | 写入/校验要点 |
| --- | --- | --- | --- |
| 用户管理 | `AccountEntity` | `@DataScope(deptField = "primaryDeptCode", userField = "code")` | 新增用户写入 `createUser`、`primaryDeptCode`；详情/修改/删除/启停/重置密码调用 `DataScopeChecker.assertAccessible(target.getPrimaryDeptCode(), target.getCode())` |
| 登录日志 | `LoginAuditLogEntity` | `@DataScope(deptField = "deptCode", userField = "accountCode")` | 登录写日志时写入账号当时的 `primaryDeptCode` 到 `deptCode` |
| 操作日志 | `OperationAuditLogEntity` | `@DataScope(deptField = "deptCode", userField = "accountCode")` | `UserOperationLogAop` 写日志时写入当前账号 `primaryDeptCode` 到 `deptCode` |

## 5. 前后端 API 契约

### 5.1 通用约定

- **HTTP 方法**：所有接口仅使用 `GET` 或 `POST`，所有 Spring 映射注解必须显式填写 `value`（如 `@PostMapping(value = "/add")`）。
- **统一响应包装**：由项目现有 `MappingJackson2HttpMessageConverterWrapper` 自动包装为 `{ "code": "200", "message": "操作成功", "data": ..., "duration": 12 }`；Controller 直接返回 VO / `Page<VO>` / `List<VO>` / `GlobalConst.SUCCESS`（`"success"`）。
- **分页入参**：继承 `PageableDTO`，包含 `pageNumber`（从 1 开始，必填）、`pageSize`（必填）、`column`（可选）、`order`（可选，`asc`/`desc`）。
- **分页返回**：Spring Data `Page<VO>`，前端读取 `data.content`（列表）与 `data.totalElements`（总数）。
- **时间格式**：`yyyy-MM-dd HH:mm:ss`（`GMT+8`）。
- **状态枚举**：
  - 部门/岗位 `status`：`1` 启用，`0` 停用。
  - 用户 `disabled`：`0` 启用（未禁用），`1` 禁用（保持与现有 `account.disabled` 语义一致）。
  - 用户 `superAdmin`：`1` 内置超级管理员，`0` 普通用户/业务管理员。

- **返回 VO（`List<DeptTreeVO>`）**：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `String` | 部门业务编码 |
| `parentCode` | `String` | 父部门编码（根为 `"0"`） |
| `ancestors` | `String` | 祖级路径 |

| `sortOrder` | `Integer` | 排序号 |

#### 2. 新增部门

| `leaderAccountCode` | `String` | 否 | 部门负责人账号编码 |
| `phone` | `String` | 否 | 联系电话 |
| `email` | `String` | 否 | 联系邮箱 |

- **返回**：`String`（`"success"`）

#### 3. 修改部门
- **URL**：`POST /bac/org/dept/update`
- **权限码**：`101-01-03`
- **请求 DTO（`DeptUpdateDTO`）**：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `String` | 是 | 部门业务编码 |
| `parentCode` | `String` | 是 | 父部门编码（不可设为自身或自身子孙节点；变更父级时须级联刷新自身及所有子孙节点的 `ancestors`） |

- **返回**：`String`（`"success"`）

#### 4. 删除部门
- **URL**：`POST /bac/org/dept/delete`
- **权限码**：`101-01-04`

#### 6. 启停岗位
- **URL**：`POST /bac/org/position/updateStatus`
- **权限码**：`101-02-05`
- **请求 DTO（`PositionStatusUpdateDTO`）**：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `String` | 是 | 岗位业务编码 |
| `status` | `Integer` | 是 | 目标状态：`1` 启用，`0` 停用 |

- **返回**：`String`（`"success"`）

### 5.4 用户管理接口（`/bac/org/user`）

#### 1. 分页查询用户
- **URL**：`POST /bac/org/user/listPageable`
- **权限码**：`101-03-01`
- **数据权限**：`@DataScope(deptField = "primaryDeptCode", userField = "code")`
- **请求 DTO（`OrgUserPageQueryDTO` extends `PageableDTO`）**：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `deptCode` | `String` | 否 | 左侧部门树点击筛选：查询该部门及其所有子孙部门下的用户 |
| `userName` | `String` | 否 | 姓名模糊搜索 |
| `loginName` | `String` | 否 | 登录名模糊搜索 |
| `phoneNumber` | `String` | 否 | 手机号模糊搜索 |
| `email` | `String` | 否 | 邮箱模糊搜索 |
| `disabled` | `Integer` | 否 | 状态筛选：`0` 启用，`1` 禁用 |

- **返回 VO（`Page<OrgUserInfoVO>`）**：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `code` | `String` | 账号业务编码 |
| `loginName` | `String` | 登录名 |
| `userName` | `String` | 用户姓名 |
| `email` | `String` | 邮箱 |
| `phoneNumber` | `String` | 手机号 |
| `disabled` | `Integer` | 是否禁用：`0` 启用，`1` 禁用 |
| `superAdmin` | `Integer` | 是否内置超管：`1` 是，`0` 否 |
| `primaryDeptCode` | `String` | 主部门编码 |
| `primaryDeptName` | `String` | 主部门名称 |
| `positionCodes` | `List<String>` | 岗位编码列表 |
| `positionNames` | `List<String>` | 岗位名称列表 |
| `roleCodes` | `List<String>` | 角色编码列表 |
| `roleNames` | `List<String>` | 角色名称列表 |
| `createTime` | `Date` | 创建时间 |

#### 2. 查询用户详情
- **URL**：`POST /bac/org/user/query`
- **权限码**：登录即可访问（Service 层调用 `DataScopeChecker.assertAccessible` 防越权）
- **请求 DTO**：`UniversalCodeDTO`（`code`：账号业务编码）
- **返回 VO**：`OrgUserInfoVO`（同上）

#### 3. 新增用户
- **URL**：`POST /bac/org/user/add`
- **权限码**：`101-03-02`
- **请求 DTO（`OrgUserAddDTO`）**：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `loginName` | `String` | 是 | 登录名（全局唯一） |
| `userName` | `String` | 是 | 姓名 |
| `password` | `String` | 是 | 密码（前端 SM2 加密或按现有登录加密规范传入，后端 BCrypt 存储） |
| `email` | `String` | 否 | 邮箱 |
| `phoneNumber` | `String` | 否 | 手机号 |
| `primaryDeptCode` | `String` | 是 | 主部门编码（须校验目标部门在当前操作人数据权限范围内，超管不受限） |
| `positionCodes` | `List<String>` | 否 | 关联岗位编码列表 |
| `roleCodes` | `List<String>` | 否 | 关联角色编码列表 |
| `disabled` | `Integer` | 否 | 初始状态：`0` 启用（默认），`1` 禁用 |

- **业务规则**：禁止通过接口创建 `superAdmin = 1` 的账号，新建用户固定 `superAdmin = 0`、`deleted = 0`、`type = "normal"`，同时同步写入 `account_dept_link`（`primary_flag = 1`）、`account_position_link`、`account_role_link`。
- **返回**：`String`（`"success"`）

#### 4. 修改用户
- **URL**：`POST /bac/org/user/update`
- **权限码**：`101-03-03`
- **请求 DTO（`OrgUserUpdateDTO`）**：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `String` | 是 | 账号业务编码 |
| `userName` | `String` | 是 | 姓名 |
| `email` | `String` | 否 | 邮箱 |
| `phoneNumber` | `String` | 否 | 手机号 |
| `primaryDeptCode` | `String` | 是 | 主部门编码 |
| `positionCodes` | `List<String>` | 否 | 关联岗位编码列表（全量覆盖） |
| `roleCodes` | `List<String>` | 否 | 关联角色编码列表（全量覆盖；内置超管不可被非超管修改） |

- **返回**：`String`（`"success"`）

#### 5. 删除用户
- **URL**：`POST /bac/org/user/delete`
- **权限码**：`101-03-04`
- **请求 DTO**：`UniversalCodeDTO`（`code`：账号业务编码）
- **业务规则**：禁止删除内置超管（`superAdmin = 1`）、禁止删除当前登录人自身；须通过 `DataScopeChecker.assertAccessible` 校验；执行软删除（`deleted = 1`）并清理 session 与关联表软删/解绑。
- **返回**：`String`（`"success"`）

#### 6. 启停用户
- **URL**：`POST /bac/org/user/updateStatus`
- **权限码**：`101-03-05`
- **请求 DTO（`OrgUserStatusUpdateDTO`）**：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `String` | 是 | 账号业务编码 |
| `disabled` | `Integer` | 是 | 目标状态：`0` 启用，`1` 禁用 |

- **业务规则**：禁止禁用内置超管（`superAdmin = 1`）与当前登录人自身；禁用时清除其 `account_session` 强制下线。
- **返回**：`String`（`"success"`）

#### 7. 重置用户密码
- **URL**：`POST /bac/org/user/resetPassword`
- **权限码**：`101-03-06`
- **请求 DTO（`OrgUserResetPasswordDTO`）**：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `String` | 是 | 账号业务编码 |
| `newPassword` | `String` | 是 | 新密码 |

- **业务规则**：非超管不可重置超管密码；须通过 `DataScopeChecker.assertAccessible` 校验。
- **返回**：`String`（`"success"`）

### 5.5 角色管理接口（`/bac/org/role`）

#### 1. 分页查询角色
- **URL**：`POST /bac/org/role/listPageable`
- **权限码**：`101-04-01`
- **请求 DTO**：`RolePageQueryDTO`（`name` 模糊搜索 + `PageableDTO`）
- **返回 VO（`Page<RoleInfoVO>`）**：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |

| `name` | `String` | 角色名称 |
| `dataScope` | `Integer` | 数据权限范围：`1` 全部、`2` 自定义部门、`3` 本部门、`4` 本部门及以下、`5` 仅本人 |
| `dataScopeName` | `String` | 数据权限范围中文名称 |
| `createTime` | `Date` | 创建时间 |

#### 2. 查询全部有效角色（下拉用）
- **URL**：`GET /bac/org/role/listAll`
- **权限码**：登录即可访问

#### 3. 新增角色
- **URL**：`POST /bac/org/role/add`
- **权限码**：`101-04-02`
- **请求 DTO**：`RoleAddDTO`（`name` 必填，`dataScope` 可选、默认 `5`）
- **返回**：`String`（`"success"`）

#### 4. 修改角色
- **URL**：`POST /bac/org/role/update`
- **权限码**：`101-04-03`
- **请求 DTO**：`RoleUpdateDTO`（`code` 必填、`name` 必填）
- **返回**：`String`（`"success"`）

#### 5. 删除角色
- **URL**：`POST /bac/org/role/delete`
- **权限码**：`101-04-04`
- **请求 DTO**：`UniversalCodeDTO`（`code` 角色业务编码）
- **返回**：`String`（`"success"`）

#### 6. 查询菜单权限
- **URL**：`POST /bac/org/role/queryPermission`
- **权限码**：`101-04-05`
- **请求 DTO**：`UniversalCodeDTO`（`code` 角色业务编码）
- **返回 VO**：`RolePermissionVO`（`codes: List<String>`，`hierarchicalList: List<PermissionHolder>`）

#### 7. 修改菜单权限
- **URL**：`POST /bac/org/role/updatePermission`
- **权限码**：`101-04-06`
- **请求 DTO**：`RolePermissionUpdateDTO`（`roleCode: String`，`permissionCodeList: List<String>`）
- **返回**：`String`（`"success"`）

#### 8. 查询角色数据权限
- **URL**：`POST /bac/org/role/queryDataScope`
- **权限码**：`101-04-10`
- **请求 DTO**：`UniversalCodeDTO`（`code` 角色业务编码）
- **返回 VO（`RoleDataScopeVO`）**：

| 字段名 | 类型 | 说明 |
| --- | --- | --- |
| `roleCode` | `String` | 角色业务编码 |
| `dataScope` | `Integer` | 当前数据范围（1~5） |
| `deptCodes` | `List<String>` | 自定义部门编码列表（仅 `dataScope == 2` 时有值） |

#### 9. 修改角色数据权限
- **URL**：`POST /bac/org/role/updateDataScope`
- **权限码**：`101-04-11`
- **请求 DTO（`RoleDataScopeUpdateDTO`）**：

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `roleCode` | `String` | 是 | 角色业务编码 |
| `dataScope` | `Integer` | 是 | 目标数据范围（1~5） |
| `deptCodes` | `List<String>` | 条件必填 | 当 `dataScope == 2`（自定义部门）时必填；其他范围清空自定义部门关联 |

- **返回**：`String`（`"success"`）

#### 10. 角色关联用户管理（沿用既有结构并迁移路径）
- `POST /bac/org/role/listRoleUserPageable`（权限码 `101-04-07`，请求 `RoleUserPageQueryDTO`，返回 `Page<RoleUserInfoVO>`）
- `GET /bac/org/role/listAllUser`（登录即可访问，返回 `List<CodeNameDTO>`，仅返回未删除用户）
- `POST /bac/org/role/addRoleUser`（权限码 `101-04-08`，请求 `RoleUserAddDTO`，返回 `"success"`）
- `POST /bac/org/role/deleteRoleUser`（权限码 `101-04-09`，请求 `RoleUserDeleteDTO`，返回 `"success"`）
